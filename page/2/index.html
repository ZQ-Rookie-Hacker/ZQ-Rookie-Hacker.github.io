1. XIMIL是一种标记语言
XML指可扩展标记语言(EXtensible Markup Language)把数据结构化后传输给对方让对方在结构化的数据中进行读取。

假设你要告诉同事“张三的座机是010-8888，手机是1380000，邮箱是zhang@xx.com”。

  • 非结构化（纯文本）：你发微信：“张三电话010-8888，手机1380000，邮箱zhang@xx.com”。
    如果同事的电脑要提取“手机号”，得写复杂的模糊匹配（万一张三写了“Tel”或者“Mobile”呢？）。

2. 标签没有被预定义，需要自行定义

这是XML与它的“表哥”HTML最本质的区别：

  • HTML（预定义标签）：浏览器只认识 [h1]（大标题）、[p]（段落）、[table]（表格）。标签是写死的，你不能自己发明一个 <帅哥> 标签让浏览器渲染，因为它不认识。
  • XML（自定义标签）：XML没有任何现成的标签库。它相当于给你一张白纸，完全由你（发送方和接收方）商量着来。比如，你们俩约定好用 <员工工号> 来传工号，用 <紧急联系人> 传亲属电话。只要双方都认这个“自定义名字”，数据就能正确读取。

3. 没有任何行为的 XML 的漏洞何处来？

绝大多数（超过95%）的XXE漏洞，核心根源就是利用了DTD声明中的“实体（ENTITY）声明”功能。

DTD声明规定：这个 XML 文档里可以出现哪些标签、标签之间的层级关系、标签里能填什么类型的数据，以及可以提前定义哪些“快捷方式（实体）

0x00:为什么可以hook？

Hook 之所以能生效，是 JavaScript 语言特性与浏览器架构共同决定的。

浏览器提供了可拦截的 API 层

浏览器将底层能力（网络请求、DOM 操作、Cookie 读写等）通过 Web API 暴露给 JS。这些 API 在底层由 C++ 实现，但在 JS 层面，它们以对象属性和方法的形式挂在 window、document、XMLHttpRequest.prototype 等全局对象上。关键在于：浏览器没有对这些 JS 层的绑定做只读保护，所以我们可以在 JS 层替换它们。

同时，浏览器是单线程执行模型，我们的 hook 脚本和目标页面代码运行在同一个 JS 上下文中，共享同一个全局作用域和对象引用。这意味着你修改了 JSON.parse，目标代码调用 JSON.parse 时就会走进你注入的函数。

在此基础上，JS 的三个语言特性让 hook 变得简单：

1. 函数是第一类对象（First-class Object）
